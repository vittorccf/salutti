# Idiomas (i18n)

A interface existe em **pt-BR** (padrão e fonte dos textos), **pt-PT**, **es** e **en**. Biblioteca: [next-intl](https://next-intl.dev) no modo **sem idioma na URL**.

## Como o idioma é escolhido

1. Cookie `salutti_locale`: gravado quando a pessoa escolhe o idioma em **Ajustes → Seu perfil** (fica em `User.locale`) e reaplicado a cada login.
   O seletor de idioma da tela de login grava o mesmo cookie.
2. Sem cookie: **pt-BR**, o idioma principal. O idioma do navegador (`Accept-Language`) não é considerado: os outros idiomas só valem por escolha explícita da pessoa.

Configuração: `src/i18n/config.ts` (idiomas, namespaces) e `src/i18n/request.ts` (carrega as mensagens). Chave que falta em pt-PT/es/en usa o texto pt-BR, então nada quebra se uma tradução atrasar.

**Moeda:** sempre real (BRL). Muda só a forma de escrever números e datas. **Fuso:** sempre America/Sao_Paulo.

## Arquivos de mensagens

`messages/<idioma>/<namespace>.json`, com os namespaces de `NAMESPACES` em `src/i18n/config.ts`:

| namespace | telas |
|---|---|
| `common` | menus, layout, rótulos de códigos do banco (`labels`), status (`status`), campos de telefone/e-mail/endereço/imagem, erros de validação (`errors`), aniversários, idioma |
| `auth` | login, verificação em duas etapas, cadastro, segurança da conta |
| `public` | página inicial, link de pagamento (`/pay`), portal do paciente (`/portal`) |
| `dashboard` | painel, primeiros passos, Saluttin |
| `settings` | Ajustes, Profissionais (equipe), LGPD, Comunicação |
| `patients` | pacientes (lista, ficha, cadastro, edição), prontuário (anamnese, evolução) |
| `schedule` | agenda (semana, nova sessão, sessão), avisos do Meet |
| `finance` | financeiro (lista, cobrança, nova cobrança, régua), fiscal, convênios e TISS |

As chaves são em inglês e agrupadas por tela: `patients.list.title`, `patients.form.fullName`. Os quatro arquivos de um namespace têm **as mesmas chaves**.

## Como escrever o código

**Server Component / Server Action**

```ts
import { getTranslations, getFormat } from "@/i18n/server";
import { labeler } from "@/i18n/labels";

const t = await getTranslations("patients.list");
const f = await getFormat();                                  // f.money, f.date, f.dateTime, f.time, f.percent, f.number
const label = labeler(await getTranslations("common.labels"));

<h1>{t("title")}</h1>
<p>{t("count", { count: patients.length })}</p>              // ICU: "{count, plural, one {# paciente} other {# pacientes}}"
<td>{f.money(charge.amount)}</td>
<td>{label("modality", appt.modality)}</td>
```

**Client Component ("use client")**

```ts
import { useTranslations, useFormat } from "@/i18n/client";
const t = useTranslations("schedule.form");
const f = useFormat();
```

**Erros de validação** das libs (`ContactError`, `UploadError`) já trazem a chave: na action, `return { erro: await errorMessage(e) }` (`src/i18n/errors.ts`). Mensagens de erro escritas na própria action: `const t = await getTranslations("<ns>.errors")` e `return { erro: t("...") }`.

**Status** (`<StatusBadge>`) e **rótulos** já são traduzidos por `common.status` e `common.labels`. Não recrie.

## Regras de texto

- pt-BR segue o design system Salutti: voz direta, sem emoji, "você".
- pt-PT: ortografia europeia (ex.: "registo", "telemóvel", "utilizador", "faturação", "contacto", "ecrã"). Use "você" com moderação, ou formas impessoais.
- es: espanhol neutro (sem voseo), "usted" evitado, use "tú" de forma neutra como em apps.
- en: inglês americano simples.
- Termos que **não se traduzem**: Salutti, Saluttin, Pix, CPF, CNPJ, CRP/CRM/CRO, TISS, ANS, LGPD, NFS-e, Receita Saúde, CEP, UF, e-Psi. Em pt-PT/es/en, pode explicar entre parênteses na primeira vez (ex.: "CPF (Brazilian tax ID)").
- Conteúdo guardado no banco (evoluções, modelos de anamnese já criados, insights já salvos, nomes) **não** é traduzido.
- A biblioteca de modelos de anamnese (`src/lib/anamnesis-library.ts`) é **conteúdo**, não interface: o modelo é copiado
  para o consultório no cadastro e a profissional edita as perguntas. Fica em pt-BR (termos clínicos e regulatórios
  brasileiros, como CRF, ANVISA e aminoglicosídeos). Uma versão por idioma só faz sentido com clientes fora do Brasil.
- Datas e valores: nunca monte string à mão; use `f.*`.
